IAM Permission Analyzer

Finds excessive permissions, risky trust and stale identities in an AWS IAM export. Runs fully in your browser; nothing is uploaded.
1. Provide IAM data (output of aws iam get-account-authorization-details)
Columns: external accounts, identities, policies, services. Border colour is the worst finding. Click a node to trace its paths; click again to reset.

How to use

Run aws iam get-account-authorization-details > iam.json in an account you are authorized to review, then upload the file. Use "Load sample" to see a demo configuration.

Permissions required (read-only)

  • iam:GetAccountAuthorizationDetails is the only permission needed. The AWS managed policy IAMReadOnlyAccess or SecurityAudit covers it.
  • Optional: iam:GenerateCredentialReport and iam:GetCredentialReport for user last-used dates.

Checks

CheckSeverity
Action * on Resource *Critical
Action * on scoped resources, Allow + NotActionHigh
Service wildcards (s3:*); iam:* is criticalHigh / Medium
Mutating actions on Resource *Medium
Privilege-escalation actions (CreatePolicyVersion, AttachUserPolicy, ...); PassRole + compute serviceHigh / Critical
Role trust: any principal, cross-account without ConditionCritical / High
Roles never used or users unused for more than 90 daysMedium

Assumptions

  • The export is complete and current. Group policies are inherited by member users, but reported once on the group.
  • Only Allow statements are evaluated for risk.

Limitations

  • Explicit Deny, permissions boundaries, SCPs, session policies and resource policies are not evaluated, so some findings may be over-reported.
  • Conditions are only checked for presence, not for strength.
  • User staleness needs PasswordLastUsed in the data (add it from the credential report); role staleness uses RoleLastUsed.
  • Corrected policies are starting templates with placeholders. Generate exact policies from CloudTrail with IAM Access Analyzer, then review.
